## Findings

1. **Fixed, not a code bug.** The global `minty` command (`~/.local/bin/minty`)
   was an editable install pointing at an abandoned test clone
   (`/Users/dhananjaykumar/minty-test/test-1/minty`, frozen at commit
   `e628e242`, 2026-08-18) instead of this repo — silently running 9-day-old
   code (missing the onboarding status lines, still showing the removed
   `/workspace <name>` REPL command). Repointed with
   `uv tool install --editable .` from this repo. Worth remembering if
   `minty` ever again shows behavior that doesn't match current source:
   check `direct_url.json` under the uv tool's site-packages before
   assuming the code itself regressed.
2. **Filed as [issue #24](https://github.com/EternalTuring/minty-core/issues/24).**
   An oversized MCP tool result (NSE's ASM surveillance list, 58,237 chars)
   triggers the Claude Agent SDK's own plain-text "exceeds maximum allowed
   tokens" redirect instead of the real envelope. `engine/tool_capture.py`'s
   `_is_error_envelope` guard only catches one specific JSON-shaped error
   (`data: {"error": ...}`) — the redirect text isn't JSON at all, so the
   guard's `json.loads` fails, is treated as "not this shape, ordinary
   content," and gets written verbatim to
   `workspace/data/surveillance_asm_2026-08-27.json` as if it were real
   data. Caught in-context this run (the model noticed the corruption and
   skipped that specific check) but that's a lucky save, not a structural
   guarantee — a later read of that cached file would trust it as real.
3. **Filed as [issue #25](https://github.com/EternalTuring/minty-core/issues/25).**
   Prompted directly by asking "is Minty actually calling our MCP tools,
   or doing its own thing" — traced H's primary-source-verification turn
   in the real session transcript. WebSearch/WebFetch genuinely aren't in
   the model's tool surface (`builtin_tools` is restricted to `["Read",
   "Write", "Bash"]`), but Bash's own scoping hook
   (`deny_out_of_scope_bash`) is a permanent no-op — `allowed_bash_prefixes`
   defaults to empty and no real entrypoint (`run.py`, `interactive.py`)
   ever overrides it. Confirmed live exercise of this gap: the model used
   raw `curl` via Bash to fetch SBI's Q1FY27 PDF directly from NSE,
   bypassing `mcp/common/nse_fetch.py`'s cache/rate-limit/backoff, leaving
   the file outside `workspace/data/`, and producing no engine auto-footer
   for that turn (the model wrote its own prose "Sources:" line instead —
   accurate this time, but not engine-verified the way every other
   grounded claim in this run was). Same category of concern as
   order-execution, which gets two independent structural enforcement
   layers — Bash/Read/Write currently get none of that, only prompt
   discipline.
